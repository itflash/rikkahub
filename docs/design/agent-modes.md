# Agent 模式与安全恢复

## 目标和范围

在现有 `GenerationLoop` 上加入可执行的模式权限，而不是仅修改系统提示词。
这是一套原生 Kotlin 实现，没有引入或复制 OpenCode 引擎。

第一阶段提供聊天、计划和执行模式、会话配置隔离、工具权限与审批续跑检查。
第二阶段增加内存内 `AgentRun`、任务进度面板和跨审批累计的模型步数预算。
第三阶段增加持久化检查点和用户确认后的安全恢复。
第四阶段增加累计 Token/执行时间预算、自动上下文压缩和串行只读子 Agent。
不包含可写子 Agent、并行改文件、递归委派或分布式任务调度。

## 用户入口

聊天输入栏的模型选择按钮旁增加模式按钮，使用 `CardGroup` 分组选择。
生成过程中不能从该按钮切换模式；先停止，再切换。
等待工具批准时可以切换模式，恢复执行前会重新校验待执行工具。

- **聊天**：默认值，保持原有工具集合、提示词和审批规则。
- **计划**：只开放由本地代码确认只读的工具，调查并给出计划，不执行修改。
- **执行**：保留已启用的工具，对所有未标记为只读的工具强制要求批准。
  只读工具已有的审批要求不会被放宽。

## 配置

`Assistant.agentMode` 是新会话默认值；`ConversationConfig.agentMode` 是会话快照。
继续使用 `Settings.getAssistantOf(conversation)` 获取运行配置。
会话内的模式更改不回写助手默认值，旧数据缺少字段时默认为 `CHAT`。

## 工具信任和执行边界

`Tool.readOnly` 默认为 `false`。只有经过审阅的本地工具定义可以显式设为 `true`。
不依据工具名称、前缀、描述、模型输出或第三方 MCP 的提示自行授予只读权限。

第一批只读工具：

- 工作区读文件、列目录；
- 记忆读取、列表；
- 历史会话检索、读取；
- 搜索、网页抓取；
- Skill 内容读取、时间查询、询问用户。

“只读”表示该工具的预期业务操作不修改工作区、记忆或外部业务状态，
不是无网络访问、无缓存写入的承诺，也不是一个新的操作系统级沙箱。
Skill 文本不拥有额外权限，不能打开 Shell 或恢复已被过滤的工具。

`AgentPolicy` 在 `GenerationLoop` 入口统一过滤/包装工具：
提供给模型的工具定义和实际执行时查找的工具列表使用同一份策略结果。
`prepareAgentToolCalls` 在初始执行和审批续跑时都处理整个未完成批次：

1. 已经执行的工具结果不改动；用户拒绝的调用不恢复。
2. 当前不可用的工具转为拒绝，包括在旧模式下已获批准的工具。
3. 当前需要批准的 `Auto` 调用转为 `Pending`。
4. 存在待批准调用时不执行整批工具；用户完成审批后再恢复。

计划模式不装配 MCP 工具，避免未使用的服务配置错误阻断只读调查。

## 绕过路径的限制

计划和执行模式都只保留已知只读的服务端搜索与 URL 上下文工具，
不开放无法经过本地审批的服务端图片生成工具。
这两个模式不发送任意自定义请求体覆盖，防止请求合并后重新注入服务端工具。
需要此类自定义请求体的提供商可能无法在 Agent 模式工作；聊天模式不受影响。

计划和执行模式都不触发后台自动记忆整理，因为它使用单独的生成循环、
不能向当前任务请求批准。记忆整理的待处理查询和实际批次筛选也检查会话模式，
防止重启扫描或先前排队的整理任务再次选中这些会话。
用户从记忆管理页面主动发起的独立整理操作不属于这个模式权限边界。

## 回归验证

主要测试：

- `AgentPolicyTest`：默认拒绝未知工具、只读标记、强制审批、旧审批失效、
  混合批次重新审批、保留用户回答、服务端工具与请求体限制。
- `ConversationConfigTest`：旧数据默认值、序列化、配置快照及会话隔离。
- `WorkspaceToolsFilesModeTest`：实际工作区工具的只读分组和写操作审批。
- `MemoryConsolidatorTest`：后台记忆整理遵守会话模式。
- `ChatServiceTest`：现有会话及生成辅助逻辑回归。

手动验收：

1. 在绑定工作区的会话选择计划模式，要求修改文件：只能调查并给出计划。
2. 切换执行模式并要求修改文件：批准前文件不变，批准后按调用执行。
3. 在写文件审批待处理时切回计划，再批准旧调用：该调用应被策略拒绝。
4. 启用 `ask_user` 后在计划模式提问：保留交互卡片和回答续跑能力。
5. 修改会话模式后新建另一会话：已绑定会话的改动不改变助手默认值。
6. 重启应用：安全检查点显示可恢复或待审批；执行结果不确定的任务只显示需核对，不自动执行工具。


## 第二阶段：运行状态与步数预算（第三阶段已扩展持久化）

`AgentRunTracker` 每次新任务独立创建，记录运行 ID、模式、步数上限、已用步骤、
实际发起的工具调用次数及当前工具。`ConversationSession` 只发布当前运行的快照，
旧任务的迟到回调不能覆盖新任务状态。

状态：准备、生成、调用工具、等待批准、等待回答、完成、失败、取消、步数用尽。
等待批准或回答不是完成；只有循环正常结束且消息最终保存成功后才标记完成。
“完成”表示本次生成流程正常结束，不是对模型所声称任务结果的独立验证。
工具调用次数包含失败的执行尝试，不包含被拒绝的工具或用户回答。

### 预算语义

- `agentMaxSteps` 默认 32，与模式一起保存到会话配置；运行时将导入值限制到 1–256。
- 模式选择面板提供 8、32、64、128 步选项。
- 一步指一轮模型生成，主任务、压缩与子任务共用步骤计数。Agent 模式不自动重试失败请求，避免隐含费用；聊天模式保留原有网络重试。
- 同一轮生成中的多个工具调用不额外消耗模型步骤。
- 审批续跑保留运行 ID、已用步骤、原始预算，只更新当前模式用于权限校验。
- 等待审批时修改步数只影响下一次新任务，不能给当前任务偷偷重置预算。
- 最后一步返回的工具仍可按正常审批流程执行；再次请求模型前检查预算。
  超限时保留已产生的消息和工具结果、暂停消息队列，不再请求模型。
- 用户发起新消息或重新生成会创建新的运行；聊天模式保留旧行为。

步数预算是模型迭代数量上限。第四阶段另外添加 Token 与执行时间预算；它们仍不是金额或外部服务计费的绝对上限。

### 生命周期与界面

输入栏上方显示任务状态、已用/总步骤、工具调用次数、当前工具及简短失败原因。
运行中和等待用户时都有“停止”按钮。停止等待中的任务无需有活跃生成 Job，
也会结束未完成工具调用，避免旧审批继续执行。

等待用户的会话会保留在当前进程内，避免切页后的空闲清理重置预算。
第三阶段起任务快照存入独立的检查点表；session 空闲回收不再丢失已提交的快照。
缺少匹配检查点时仍拒绝续跑，不会默默从零重置预算。由聊天模式的旧审批切入 Agent 模式时，也需要新任务。

增加 `AgentRunTest`、`ConversationSessionTest` 和配置回归测试，覆盖累计预算、
终态、等待时停止、会话保留、过期回调隔离及缺失运行状态时拒绝恢复。


## 第三阶段：持久化检查点与安全恢复

### 数据与原子性

Room 数据库升级至 **31**，通过 30→31 自动迁移增加 `agent_checkpoints` 表。
每个会话保存一份最新快照，删除会话时通过外键级联删除；这不是完整的历史运行审计表。
表独立于 `ConversationEntity`，普通标题、设置或会话整行保存不能覆盖执行日志。
写入事务还校验当前运行 ID；只有显式开始新任务才能替换旧运行，迟到的旧回调不能覆盖新日志。

检查点包含版本、原始运行 ID、状态、预算与累计计数、正在执行的工具调用 ID、
实际生成的消息前缀长度、阶段以及上下文指纹。实际消息保存在现有消息表中；
检查点与对应消息节点在同一个数据库事务中提交，不在每个流式 token 上落库。

指纹绑定会话/助手、当前消息分支、消息内容、工具输入和结果、工作区、工作目录、
会话模型及其它会话级运行配置。标题、置顶、审批决定、Agent 模式和下一任务步数设置
不影响指纹；模式切换仍由现有工具权限层处理，当前运行预算保持不变。
指纹用于检测意外变更，不是抵御本地数据库篡改的加密认证机制。

### 写入顺序

1. 请求模型前：递增已用步骤，保存 `MODEL_REQUEST`。重启不退还已使用步骤。
2. 收到完整模型结果后：保存 `READY`；若无需工具且回答已完成，保存 `FINISHED`。
3. 等待用户时：保存 `WAITING_USER`，而不是把任务标为完成。
4. **工具执行前**：提交 `TOOL_IN_FLIGHT` 及工具调用 ID；写入失败就终止，不能执行工具。
5. **每个工具完成后**：立即提交该工具的结果并清除执行中标记，再进入下一个工具。
   不等整批工具执行完才保存，因此重启后不会重复执行已提交结果的调用。
6. 完成、失败、预算耗尽或用户停止：保存终态。终态写入失败时保留旧执行中标记，
   重启后宁可要求核对，也不假设工具未曾执行。

### 恢复规则

加载会话只读取和恢复 UI，不发起模型请求或工具调用。

- `READY` / `MODEL_REQUEST`：显示“已暂停 · 可恢复”，用户点击“继续”后续跑。
- 待批准/待回答：恢复交互状态。**上一进程已经批准但尚未执行的调用重新要求批准**；
  已执行结果、拒绝决定和用户回答保持不变。
- `TOOL_IN_FLIGHT`：显示“已中断 · 需核对”，不提供自动继续；请核对实际副作用后发起新任务。
- 完整回答已提交：恢复为已完成，不额外请求模型。
- 指纹不符、检查点损坏或未知版本：拒绝恢复，提示重新发起任务。
- 历史节点重新生成：恢复时使用保存的消息前缀，而不是错误地把后续旧消息加入上下文。

继续旧 Agent 任务要求处于计划或执行模式；切到聊天模式后需要发起新请求，不能用旧审批默默重置预算。
同一运行保留原 ID、原预算和累计步骤。模型请求中断后手动重试会消耗新的一步，
可能造成提供商再次计费；不能把该机制理解为远端请求去重或退款。

非只读工具如果已经开始执行却抛出异常，也可能已经产生副作用，因此 Agent 任务转为
需核对状态，不把错误交给模型自动重试。工具执行与本地结果落库之间发生进程崩溃时，
无法证明外部操作的最终结果。本实现**不承诺外部操作恰好执行一次**，而是阻止不确定结果的重放。

### 验证

- `AgentCheckpointTest`：序列化、累计预算、未知结果阻断、指纹变化、历史消息前缀、旧批准重置。
- `ConversationSessionTest`：恢复不启动任务，旧检查点不能覆盖活跃任务。
- `AgentCheckpointRepositoryTest`（Android 仪器测试）：事务回滚、会话删除级联、普通保存隔离，
  以及使用假 Provider 驱动真实 `GenerationLoop`，验证落库失败时不执行、执行中断后阻断、
  批次部分完成后的续跑去重和历史上下文恢复。
- `Migration_30_31_Test`：迁移保留原会话，检查点表建立及级联删除正确。


## 第四阶段：资源预算、自动压缩、子 Agent

### 配置和默认值

新增会话快照字段：`agentMaxTokens`（默认 200000）、`agentMaxMinutes`（默认 15）、
`agentAutoCompact`（默认开启）、`agentSubtasks`（默认开启）。
模式面板可调整额度和开关，任务进度展示已用 Token、累计执行时间、压缩次数及最近子任务。
额度与两个能力开关在新任务启动时固定，审批续跑继续使用原设置；等待审批时修改设置只影响下一次任务。

### Token 和时间

所有主模型请求、摘要请求和子任务请求共用同一份计数。
发请求前先保守估算输入并预留输出，把预留记录写入检查点，同时限制请求的输出 Token 参数。
收到提供商用量后以本次请求的用量结算；不复用上一次消息的 usage。
没有用量、请求失败或中断时保守计入整笔预留并标记“含估算”。恢复时尚未结算的预留不退回。

文本使用 UTF-8 字节数等做保守估计，多媒体使用固定额度，并非每个提供商的精确 tokenizer。
因此预算可能提早停止；服务端不遵守输出上限、服务端工具及计费差异也可能造成实际费用超出估计。
**此功能不是账单金额保证，也不能撤销已经发送的远端请求。**

执行时间在每段运行开始计时，等待批准/回答时暂停，续跑继续累计。
超时取消当前协程及其子任务；正在执行的外部操作仍需人工核对实际结果。
进程意外退出时无法知道精确结束时间，恢复时保守计入检查点到重新加载之间的时间，最多补记一个完整预算。
等待用户的正常检查点已经关闭计时，不会把审批等待计入预算。

### 自动上下文压缩

估算上下文达到模型窗口约 60% 时，将较早、已完成的消息汇总为摘要，保留最近四条消息。
不跨越未完成工具调用；工具输入、结果、拒绝原因和文件路径会加入摘要材料。
新摘要承接上一份摘要。摘要与覆盖范围保存在运行检查点，原始聊天记录不删除、不替换。
对于一条助手消息里积累大量工具结果的情况，也会汇总较早的已完成工具结果，保留最新结果；
发送给模型时仍保留工具调用与非空结果配对，原始结果继续保存在聊天历史。
模型后续请求使用“摘要 + 保留消息”，界面仍显示完整记录。

摘要请求不开放任何工具，也计入共享预算。空摘要、压缩材料过大或剩余窗口不足时明确停止，
而不是静默丢失历史。单个超长材料可能需要手动压缩或更大上下文模型。
摘要是有损模型生成，不能视为精确审计记录；超长源内容的截断会显式注明，原始记录仍保留。

### 子 Agent

模型可调用 `delegate_research(task)` 委派自包含的调查或审查任务。
子任务上下文独立，只接收显式任务和受限工具定义，不自动继承父任务全文、系统提示或记忆。
结果以工具结果回到父任务；父任务需要自行验证证据，不能把子任务输出当成更高优先级指令。

约束：

- **串行、只读**；只继承父工具集合中明确标记只读的工具。
- 不开放写文件、Shell、未知 MCP、`ask_user` 或再次委派。
- 即使是只读工具，只要当前参数需要审批，也拒绝在子任务中执行。
- 每个子任务最多 8 轮生成、每轮最多 16 个工具调用，共享父任务所有资源预算。
- 用户停止或父任务超时，会向子任务传播取消。
- 子任务状态和简短结果随父任务检查点保存；只保留最近 8 项摘要，界面显示最近 2 项。
- 中断时不自动重放子任务，继续遵守工具执行中检查点的保守恢复规则。

### 验证

新增 `AgentResourceTest`、`AgentContextTest`、`AgentSubtaskTest` 及会话配置隔离测试。
Android 仪器测试驱动真实 GenerationLoop，覆盖 Token 预检、慢请求超时取消、
自动压缩保留历史、摘要持久化、子任务共享预算/隔离上下文，以及后续请求缺失 usage 时的保守计数。
