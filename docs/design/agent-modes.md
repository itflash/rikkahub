# Agent 模式：第一阶段

## 目标和范围

在现有 `GenerationLoop` 上加入可执行的模式权限，而不是仅修改系统提示词。
这是一套原生 Kotlin 实现，没有引入或复制 OpenCode 引擎。

第一阶段提供聊天、计划和执行模式、会话配置隔离、工具权限与审批续跑检查。
第二阶段增加内存内 `AgentRun`、任务进度面板和跨审批累计的模型步数预算。
尚未实现持久化检查点、跨进程恢复、累计 Token/时间预算、自动上下文压缩或子 Agent。

## 用户入口

聊天输入栏的模型选择按钮旁增加模式按钮，使用 `CardGroup` 分组选择。
生成过程中不能从该按钮切换模式；先停止，再切换。
等待工具批准时可以切换模式，恢复执行前会重新校验待执行工具。

- **聊天**：默认值，保持原有工具集合、提示词和审批规则。
- **计划**：只开放由本地代码确认只读的工具，调查并给出计划，不执行修改。
- **执行**：保留已启用的工具，对所有未标记为只读的工具强制要求批准。
  只读工具已有的审批要求不会被放宽。

## 配置

`Assistant.agentMode` 是新会话默认值；`ConversationConfig.agentMode` 是会话快照。
继续使用 `Settings.getAssistantOf(conversation)` 获取运行配置。
会话内的模式更改不回写助手默认值，旧数据缺少字段时默认为 `CHAT`。

## 工具信任和执行边界

`Tool.readOnly` 默认为 `false`。只有经过审阅的本地工具定义可以显式设为 `true`。
不依据工具名称、前缀、描述、模型输出或第三方 MCP 的提示自行授予只读权限。

第一批只读工具：

- 工作区读文件、列目录；
- 记忆读取、列表；
- 历史会话检索、读取；
- 搜索、网页抓取；
- Skill 内容读取、时间查询、询问用户。

“只读”表示该工具的预期业务操作不修改工作区、记忆或外部业务状态，
不是无网络访问、无缓存写入的承诺，也不是一个新的操作系统级沙箱。
Skill 文本不拥有额外权限，不能打开 Shell 或恢复已被过滤的工具。

`AgentPolicy` 在 `GenerationLoop` 入口统一过滤/包装工具：
提供给模型的工具定义和实际执行时查找的工具列表使用同一份策略结果。
`prepareAgentToolCalls` 在初始执行和审批续跑时都处理整个未完成批次：

1. 已经执行的工具结果不改动；用户拒绝的调用不恢复。
2. 当前不可用的工具转为拒绝，包括在旧模式下已获批准的工具。
3. 当前需要批准的 `Auto` 调用转为 `Pending`。
4. 存在待批准调用时不执行整批工具；用户完成审批后再恢复。

计划模式不装配 MCP 工具，避免未使用的服务配置错误阻断只读调查。

## 绕过路径的限制

计划和执行模式都只保留已知只读的服务端搜索与 URL 上下文工具，
不开放无法经过本地审批的服务端图片生成工具。
这两个模式不发送任意自定义请求体覆盖，防止请求合并后重新注入服务端工具。
需要此类自定义请求体的提供商可能无法在 Agent 模式工作；聊天模式不受影响。

计划和执行模式都不触发后台自动记忆整理，因为它使用单独的生成循环、
不能向当前任务请求批准。记忆整理的待处理查询和实际批次筛选也检查会话模式，
防止重启扫描或先前排队的整理任务再次选中这些会话。
用户从记忆管理页面主动发起的独立整理操作不属于这个模式权限边界。

## 回归验证

主要测试：

- `AgentPolicyTest`：默认拒绝未知工具、只读标记、强制审批、旧审批失效、
  混合批次重新审批、保留用户回答、服务端工具与请求体限制。
- `ConversationConfigTest`：旧数据默认值、序列化、配置快照及会话隔离。
- `WorkspaceToolsFilesModeTest`：实际工作区工具的只读分组和写操作审批。
- `MemoryConsolidatorTest`：后台记忆整理遵守会话模式。
- `ChatServiceTest`：现有会话及生成辅助逻辑回归。

手动验收：

1. 在绑定工作区的会话选择计划模式，要求修改文件：只能调查并给出计划。
2. 切换执行模式并要求修改文件：批准前文件不变，批准后按调用执行。
3. 在写文件审批待处理时切回计划，再批准旧调用：该调用应被策略拒绝。
4. 启用 `ask_user` 后在计划模式提问：保留交互卡片和回答续跑能力。
5. 修改会话模式后新建另一会话：已绑定会话的改动不改变助手默认值。
6. 重启应用：保存后的会话模式保留；不宣称正在执行的任务能跨进程恢复。


## 第二阶段：运行状态与步数预算

`AgentRunTracker` 每次新任务独立创建，记录运行 ID、模式、步数上限、已用步骤、
实际发起的工具调用次数及当前工具。`ConversationSession` 只发布当前运行的快照，
旧任务的迟到回调不能覆盖新任务状态。

状态：准备、生成、调用工具、等待批准、等待回答、完成、失败、取消、步数用尽。
等待批准或回答不是完成；只有循环正常结束且消息最终保存成功后才标记完成。
“完成”表示本次生成流程正常结束，不是对模型所声称任务结果的独立验证。
工具调用次数包含失败的执行尝试，不包含被拒绝的工具或用户回答。

### 预算语义

- `agentMaxSteps` 默认 32，与模式一起保存到会话配置；运行时将导入值限制到 1–256。
- 模式选择面板提供 8、32、64、128 步选项。
- 一步指一轮模型生成；自动网络重试属于该轮，不是新的步骤。
- 同一轮生成中的多个工具调用不额外消耗模型步骤。
- 审批续跑保留运行 ID、已用步骤、原始预算，只更新当前模式用于权限校验。
- 等待审批时修改步数只影响下一次新任务，不能给当前任务偷偷重置预算。
- 最后一步返回的工具仍可按正常审批流程执行；再次请求模型前检查预算。
  超限时保留已产生的消息和工具结果、暂停消息队列，不再请求模型。
- 用户发起新消息或重新生成会创建新的运行；聊天模式保留旧行为。

这是模型迭代预算，不是金额、Token、工具次数或耗时的硬上限。

### 生命周期与界面

输入栏上方显示任务状态、已用/总步骤、工具调用次数、当前工具及简短失败原因。
运行中和等待用户时都有“停止”按钮。停止等待中的任务无需有活跃生成 Job，
也会结束未完成工具调用，避免旧审批继续执行。

等待用户的会话会保留在当前进程内，避免切页后的空闲清理重置预算。
任务结束后仍遵循现有 session 空闲回收，因此历史进度不是持久化任务记录。
进程重启后无法恢复运行计数；Agent 审批续跑会明确报错，不会默默从零重置预算。
先停止旧调用，再发起新任务。由聊天模式的旧审批切入 Agent 模式时，同样需要新任务。

增加 `AgentRunTest`、`ConversationSessionTest` 和配置回归测试，覆盖累计预算、
终态、等待时停止、会话保留、过期回调隔离及缺失运行状态时拒绝恢复。
