## 适配时额外保留的边界

- 计划／执行模式不能因为自动做梦开关而进入后台记忆写入流程。
- 原 `rikkahub` 搜索配置保留反序列化类型，以免旧设置/备份读取失败；仅作为禁用兼容项，绝不请求原版搜索后端或发送旧密钥。
- 更新检查只接受本仓库的正式数字版本，忽略 `dev`、`nightly`、草稿和预发布；按设备 ABI 选择 APK。
- MCP 授权优先使用本用户配置或动态注册，不假设存在本分支 GitHub Pages 客户端元数据，也不使用上游身份。
- CI 运行归档签名包、mapping、SHA-256 和来源 manifest。dev 构建为预发布，不抢占正式版本的 latest 标记。

## 验证与发布

- 本机只构建 Debug 和测试包，用于编译、单元测试与设备回归。
- Release 必须由 GitHub Actions 为完整目标提交构建，发布前核对 artifact 的 SHA、run ID 和包内版本。
- 全量 lint 的既有错误不在此上游合并中一并清理；不可宣称 lint 全通过。
- 发布日志须经用户确认后再创建正式 tag/Release。
